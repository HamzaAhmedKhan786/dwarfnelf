# Security and Privacy Architecture
Threats: hostile model files, prompt injection in RAG, malicious tool output, supply-chain compromise, localhost CSRF/DNS rebinding, unauthorized filesystem access, data exfiltration, malicious dataset archives, model license misuse and unsafe updates.
Controls: loopback-only binding; random per-install pairing secret stored in OS credential vault; origin checks and anti-CSRF; signed releases/SBOM; checksum verification; safe archive extraction; sandboxed parsers/tools; per-domain ACL; allowlisted network; least-privilege OS service; secret redaction; encrypted corpus optional; audit trail; backup encryption; dependency scanning and vulnerability response.
Model and dataset manifests must include source, hash, license and provenance; untrusted pickle execution prohibited. Native model parsers and embedded database libraries are fuzz-test targets. High-risk medical/legal output must display evidence limitations, not imply licensed professional advice.
